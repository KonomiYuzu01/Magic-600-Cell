## 1. Goal and acceptance

The owner wants the jumbling tutorial's main figures to be pictures of the actual puzzle (22 October 2026). The
full-state page `V/full.html` (`V/full.js`) already draws all 259,800 stickers of all 177,120 pieces from a state in
the render data contract `magic600-jumbling-render/1` (`research/jumbling/render-contract.md`; `V/README.md`,
"Full-state page"). It only loads the fixture menus S4, I_a and I_b. Build the path from a tutorial runner record to a
screenshot of that page:

1. `V/export_tutorial.py <run dir> --step N --when before|after --out <dir>`:
   - reads a `runner-run/3` record (`run.json`, `start-table.json`, `words/*.json`; format in the stage 13 README,
     section 2), replays from the start table through the words of steps 0..N-1 (`before`) or 0..N (`after`) with
     the simulator, and checks the replayed digest against `steps[i].before.digest` / `steps[i].after.digest` at
     every step boundary it passes (and `start.digest` at the start). Any mismatch: exit non-zero, write nothing;
   - may start from a later table the record names (for example `tables/bulk-end.json`) when its digest matches the
     record, to skip long replays;
   - writes `<dir>/header.json` and the three state arrays exactly as `research/jumbling/fixtures/wj.py` `export`
     does (reuse `wj.arrays`, read-only), so the page's existing loader and digest checks accept them;
   - writes `<dir>/tutorial.json` (format `magic600-tutorial-shot/1`): repository-relative record path, sha256 of
     `run.json` and of each word file used, step index, `when`, phase, subphase, rule, letter count, the letters
     themselves when there are at most 64 (else their sha256), the caps the letters name, off-lattice count, digest,
     and `moved`: `{file: "moved.i32", count, sha256}` for the sorted ids of the pieces whose pose differs between
     the before and the after state of step N (the same set for both `when` values); writes `<dir>/moved.i32`;
   - refuses a record whose start seed is in 9011..9073, an `--out` that exists and is not empty, and an `--out`
     inside the record directory; never writes into the record.
2. A screenshot mode in `V/full.js` and `V/full.html`, active only with `?shot=<name>` (`^[A-Za-z0-9_-]{1,64}$`):
   - loads `tutorial/<name>/header.json`, its arrays, `tutorial.json` and `moved.i32` relative to the page, with the
     same digest checks as the menus; no fixture overlay, sweep, panels or other chrome; the canvas fills the page;
   - `w` and `h` set the canvas size in CSS pixels (default 1600 x 1000);
   - `emph=moved` (default) draws the moved pieces as now and every other sticker dimmed toward the background;
     `emph=none` draws all stickers as now;
   - `view=global` (default) uses the page's default camera; `view=local` rotates the 4D view (Q) so that the centre
     of the first cap the letters name is on the view axis and frames that cap and its neighbours; `proj=persp`
     (default) or `stereo` as the page already offers;
   - when the first complete frame is drawn, sets `document.documentElement.dataset.shotReady = "1"`, or `"error"`
     with the message in `dataset.shotError`.
   Without `?shot`, the page behaves exactly as before, and `V/check_full.mjs` keeps passing.
3. `V/capture_tutorial.mjs --data <dir> --list <shots.json> --out <dir> [--vendor DIR] [--check]`:
   - serves `V` and `<dir>` (as `tutorial/`) on 127.0.0.1, answers only the page's own files, the vendored three.js
     files (`--vendor`, same pinned SHA-256 as `V/check_full.mjs`) and the tutorial data, and fails on any other
     request; Playwright Chromium (`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`), SwiftShader, device scale factor 1;
   - for each entry `{name, state, view, proj, emph, w, h}` of the list, loads the page, waits for `shotReady`, and
     saves the canvas as `<out>/<name>.png`;
   - writes `<out>/manifest.json`: node, Playwright and Chromium versions, sha256 of `full.html`, `full.js` and the
     two three.js files, and per shot its parameters, the state's header digest, the sha256 of its `tutorial.json`
     and of the PNG;
   - `--check` renders the list again into a temporary directory and compares each PNG's sha256 with the manifest;
     exit 1 and name the shots that differ.
4. `V/test_export_tutorial.py` (unittest, runs in a few minutes), and a short "Tutorial screenshots" section in
   `V/README.md` (English, plain, how to run 1 to 3).

Acceptance (the contract's check): `test_export_tutorial.py` passes. It must at least test, on the committed
record `R/d0-s7001/run`: step 0 `before` and `after` give the recorded digests (`1438ebed…`, `ab254e2a…`), off
counts 26,519 and 23,422, and 3,097 moved pieces; header and array hashes agree with the files and with
`wj.arrays`; tampered word, seed 9050, non-empty `--out` and `--out` inside the record are refused with nothing
written. It also runs `node --check` on `V/full.js` and `V/capture_tutorial.mjs` (skipped with a note if `node` is
missing). If Chromium starts in your sandbox, also run one capture of step 0 `before`, global, with `--vendor`
pointing at a directory you build from the pinned files only if they are already on disk; otherwise say so, and the
integrator runs it.

Out of scope: annotations and captions on the images, colours (provisional; the owner decides G1 to G6), other
renderers, the D3D12 path, performance.

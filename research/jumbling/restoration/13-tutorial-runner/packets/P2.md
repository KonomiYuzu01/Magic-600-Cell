### 4.4 Result mapping (plan, section 0 result table and P2; decisions marked)

The plugin first checks `Child`. Only after that does it read the kernel's record. Only two rows below are not
`error` without a step: the kernel's own clock (`budget`) and exhaustion (`stuck`). Every crash, every missing,
truncated or inconsistent record and every digest mismatch is `End('error', ...)`, which ends the run `error` at once
(section 4.1; I0-01).

| Kernel outcome | Plugin returns |
|---|---|
| `child.timeout` (the runner's kill) | `End('timeout', 'kernel_wall_clock')`, one attempt with `timed_out: true`. No file of that call is read, whether or not `run.json` exists |
| `child.cancelled` (a signal; decided here) | `End('error', 'cancelled')` |
| nonzero exit | `End('error', 'kernel_error')` when `run.json` reads `result: 'error'` (keep its `reason` in `details` as `kernel_reason`); otherwise `End('error', 'kernel_exit')`, also when `run.json` still holds the start placeholder (`result: 'budget'`), which is never read as a budget |
| exit 0, `run.json` missing or unreadable | `End('error', 'kernel_record_missing')` |
| exit 0, record inconsistent (decided here; see the checks below) | `End('error', 'kernel_record_invalid')` |
| `lattice` with one step and `off_after` 0 | a `Proposal` (`r22d25_search.py:553-555`). The runner then reports the phase result `lattice` (`runner.py:624-625`) |
| `lattice` in any other shape (no step, more than one step, `off_after` not 0; decided here) | `End('error', 'kernel_record_invalid')` |
| `budget`, one step, and some ledger cursor has the key `max_steps` | a `Proposal`: a step, not a budget end (:557-561) |
| `budget`, no step, no ledger cursor has the key `max_steps`, and `stop_family` (section 4.2) is not null | the kernel's own clock: `End('budget', 'kernel_clock')`, one attempt with `timed_out: true` and that `stop_family` (plan §0 Clocks: "the kernel's `budget` with a clock cursor"; plan P2: "`budget` with any other ledger cursor is the kernel's own clock") |

| `stuck`, no step, every ledger row `exhausted` | `End('stuck', 'kernel_exhausted')`, one attempt with `timed_out: false`. The details name the catalogue `r22d25-cat/1`: this stuck covers only that catalogue (R22D-55) |
| `stuck` with a step, or with a row not `exhausted` (decided here: the kernel guarantees both at :484-488 and :553-561, and R22D-55 forbids reading an unfinished family as exhausted) | `End('error', 'kernel_record_invalid')` |
| `unsupported`, reason `d19_missing` | `End('error', 'd19_missing')` (R3-03: a missing dependency) |
| `unsupported`, reason `height_above_6` | `End('error', 'invariant_height_above_6')` (the high entry test excludes it) |
| `unsupported`, any other reason | `End('error', 'kernel_unsupported')` |
| any other `result`, `error` with exit 0 included | `End('error', 'kernel_record_invalid')` |

Every `End` the plugin returns carries exactly one attempt row (section 4.6). Its `timed_out` is true only for
`kernel_wall_clock` and `kernel_clock`; a cancel is not a clock.

The record checks (decided here; each failure is `kernel_record_invalid`). On every record read after exit 0,
before any row of the table above is chosen:
- `format` is `r22d25-run/1` and `catalogue` is `r22d25-cat/1`;
- `start.digest` and `start.off` equal `ctx.snapshot()`, so that no result, stuck included, is read about another
  state;
- `steps` is a list and `ledger` a dict of rows, each with a string `status`;
- `limits` equals `{'direct': 244, 'S': 244, 'T': 720, 'ST': 964}` (`DEFAULT_LIMITS`, `r22d25_search.py:34`), the
  limits the CLI always passes (`Limits` defaults, :38-45, used at :637-638). Smaller limits would make a `stuck`
  cover less than the catalogue it names (`README.md:919`, R22D25-contract-06);
- the ledger has a row for each of `F1, F2, F3, d19, S, ST, T1` (`FAMILIES`, :36; the CLI registers no provider,
  :638); extra rows, such as a provider's, are accepted, so that "every ledger row `exhausted`" is never true of a partial or empty ledger.

Before a `Proposal`, in addition:
- exactly one step, with `index` 0 and `word` equal to `'words/00000.json'`;
- `family` is one of `F1, F2, F3, d19, ST, T1`;
- `kind` is `landing` or `lowering`;
- `target` is a non-empty, sorted list of ints;
- `high_exact` is a bool;
- `off_before` equals the snapshot's `off`;
- `input_digest` equals the current digest;
- the word file has exactly the three keys, its `input_digest` and `output_digest` equal the row's, and its length
  equals `letters`;
- a landing has `off_after < off_before`;
- a lowering has `heights_after['6']`, taken as 0 when missing, below the snapshot's n6 (`r22d25_search.py:586-589`);
- for ST, `S_length + T_length == letters` and both are ≥ 1.

The runner's replay then checks every twist and the claimed end digest (`record_step`, `runner.py:701-707`;
`Mechanics.apply_word`, :258-267). A mismatch there ends the run `error` (section 4.1).

### 4.5 Clocks (plan, section 0 Clocks; R3-01)

- Development mode:
  - the kernel gets `--seconds ctx.child_clock('kernel_seconds')`, which is `--kernel-seconds`;
  - the call gets `ctx.execute(..., seconds=ctx.wall('kernel_seconds') + ctx.budgets['kernel_wall_margin'])`.
- Acceptance mode:
  - the kernel gets `--seconds 1e9` (`CLOCK_SENTINEL`);
  - the call gets `ctx.execute(..., seconds=None)`, so the runner never kills it.
- The kernel's clock does not cover input loading or the snapshot: `Budget` is checked only inside the search loops
  (`r22d25_search.py:629-638`, :537). That is why the runner adds a margin. Measured by I0 on 20 October 2026
  (`README.md:779-783`; headless Linux, four cores, two other single-threaded jobs running): the kernel with
  `--seconds 1` at the R22D-36 state took 18.6 s, result `budget`, no step.
- The nested D19 call gets `str(budget.remaining())`, about 999,999,999 s in acceptance mode, and `timeout` of the
  same size. `subprocess.run` accepts `timeout=1e9` without pipes, and the kernel's call uses `DEVNULL`
  (`r22d25_search.py:347`). With pipes, `capture_output=True` raises `OverflowError` above 2³¹ − 1 ms, about
  24.9 days (measured, 20 October 2026: 2,147,483.6 s passed, 2,147,483.7 s failed; `README.md:280-283`). No path
  here passes the sentinel to a capturing call.
- A non-finite value is rejected by `Budget` (:64-65) and by D19 (`r22d19_rule.py:684-685`). Never pass `inf` or None
  as a child clock, and never write `inf` or NaN into the record: `atomic_json` uses `allow_nan=False`
  (`runner.py:83-92`).

### 4.6 What a proposal holds (plan, sections 1 and 3 P2)

- `phase='high'`, `subphase=None`, `rule='r22d25/<family>'`, `standing='rule'`, `gate='r22d25'`.
- `contract` is `kernel_landing` or `kernel_lowering`, from the row's `kind`.
- `word` is the kernel's word file, as read.
- `tree`:

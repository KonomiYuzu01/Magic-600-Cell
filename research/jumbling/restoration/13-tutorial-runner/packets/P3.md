### 4.2 The player (`literal_lattice.py`) and the observer edit

- What is there:
  - `Program(nodes, trees)` (:115-200) validates a topologically ordered DAG: a node's children have smaller indices
    (`factor(..., limit)`, :162-167). `words[j]` is the move tuple of a `word` or `path` leaf (:128-146), `lengths[j]`
    the expanded length. `leaves(node, sign)` (:169-191) yields signed leaves in played order: a `conj` node
    `{x, u, us}` expands to (u, −us), (x, sign), (u, us) (:185-187); a `prod` in order, or reversed with negated signs
    when the sign is −1 (:188-191). `expand` (:193-200).
  - `simulator()` (:203-212) returns `(sim, orient.set_pose_table, ctx, I_a menu)`.
  - `LatticePlay` (:224-336): `play(move)` gathers the labels and, unless `defer_poses`, moves the poses (:278-282);
    `transport_word` (:301-323); `state()` (:325-336) rebuilds the exact simulator state, including rotations the
    labels do not see, and checks its labels.
  - `play(restore_dir, start_table, run_index=0, library=None, seconds=None)` (:350-559): input checks (:401-479);
    `seconds=None` means no deadline (:402, :480); corrections first when the order is not `retained-first`
    (:481-484, `post_correction_digest`); the retained loop over factors and leaves (:486-516) with `defer_poses` for
    every `word` leaf (:497) and the composed field at the leaf's end (:509-512); the factor check (:513); the
    retained-first junction against T (:517-523), then C on the played state (:527-528); `final` (:532-533) and the
    identity requirement (:534); the budget and failure paths (:538-556).
  - `main()` (:562-574) and its only stdout line (:573):
    `print(json.dumps({'result': report['result'], 'failure': report['failure'], 'played': report['played']}))`.
  - The report format `literal-lattice/1` is pinned by `test_literal_lattice.py:88-164` (`ReportChecks`).
- The edit (plan P3, "edit or wrap — chosen: edit"; a wrapper would copy the 130 lines of input checks at :350-479):
  - Signature: `play(restore_dir, start_table, run_index=0, library=None, seconds=None, observer=None)`.
  - `observer=None`: the same behaviour as today, report key for key; the CLI and its report are unchanged. Guard
    every new line with `if observer is not None`.
  - With an observer: `defer_poses` stays False for every leaf, so poses move twist by twist (:281-282) and
    `transport_word` is never called.
  - The observer protocol (decided here; the plan lists the leaf codes, each factor boundary, each correction twist
    and the final state; `begin` and `correction_end` are added so that the trees come from the program actually
    played and every correction step has an exact end digest):
    - `begin(program, factors, corrections, order)`: once, after every input check has passed (after :480) and
      before the first played twist. `program` is the `Program`, `factors` the run's `[node, sign]` list,
      `corrections` the validated `run['corrections']`, `order` `'retained-first'` or `'corrections-first'`.
    - `leaf(node, sign, codes)`: after each leaf's twists are played; `codes` are the leaf's I_a codes in played
      order (section 4.4). When a budget stop interrupts a leaf, the played prefix is delivered, so the stream always
      equals the twists played.
    - `factor_end(index, state)`: after factor `index` (global index in `factors`) and its check at :513. `state` is
      a zero-argument callable that returns the exact played `State` (`LatticePlay.state()`); the observer calls it
      only where it needs a digest (it costs a full state rebuild).
    - `correction_twist(code)`: after each played correction twist, never for the construction of T (:518-519).
    - `correction_end(index, state)`: after the last repetition of correction entry `index`; `state` as above, returning
      the live simulator state.
    - `final(state)`: once, with the final exact `State`, after `report['final']` is set (:532-533) and before the
      identity requirement (:534).
  - The observer must not change any state it is given. An exception raised by the observer must never end in
    `solved`.
- Recorded behaviour the edit must keep (README :572-616): `final.digest` is the digest of the state actually played
  and need not be `SOLVED`, because labels do not fix exact poses (README :594-598); at a retained-first junction C is
  played on the played state Y·R, not on T (README :590-593, finding LLP-false-pass-01).

### 4.4 I_a letters and the `ia16` stream

- A signed primitive id m (±1..±1200) is the twist `sim.primitive(ctx, m)` (`sim/twists.py:348-357`): grip
  `(|m| − 1) // 2`, K+ index `kp.gen_idx[|m| − 1]` (`sim/kplus.py:69`), inverted by `kp.inv` when m < 0, matrix
  `kp.matrix(index)` (`sim/kplus.py:115`).
- An I_a letter (grip, item) is the twist `Twist(ctx, grip, restore.element(M, grip, item), 'menu', {'menu': M.name})`
  with `element(M, c, i) = f·items[i]·fᵀ`, `f = M.frame(c)` (`theory/restore.py:67-69`; `TwistMenu.frame`,
  `sim/twists.py:488-489`), where `M = restore.menu('I_a')`, the menu the runner (`runner.py:226`) and the checker use;
  it is built by the same `wj.make_menu(ctx, 'I_a')` as the player's menu (`theory/restore.py:61-64`,
  `literal_lattice.py:212`), on the same context. `TwistMenu.contains` (`sim/twists.py:507-509`) tests `fᵀ·g·f`
  against the base items (`items` :474, `_keys` :475; items are distinct). The I_a menu contains A4 (:478), so every
  primitive is a menu letter at its grip; `theory/buffer.py:150-160` builds the same correspondence through
  `kp.index_of_matrix`.
- The code of a played twist is `60·grip + item` with `item` the unique index whose base matrix equals `fᵀ·g·f`
  (decided here: compute it exactly, once per signed primitive, 2,400 entries, and once per correction twist; fail
  with a named check, for example `primitive_letter` or `correction_letter`, when no item or more than one matches).
  The inverse of a code is `60·grip + inverse item`, the item with the transposed base matrix (as
  `Mechanics.inverse_word`, `runner.py:269-272`), and the code of −m is the inverse of the code of m.
- One source for the codes (decided here): the observer edit in `literal_lattice.py` computes them, only when an
  observer is given, from the player's own I_a menu (`simulator()`, :203-212) and the twist it plays (the signed
  primitive's matrix, or the correction twist's grip and matrix), and hands them to the observer (`leaf`,
  `correction_twist`, section 4.2). The observer, the plugin and its child map no twist to a code themselves. "The
  menu's inverse table" (sections 4.6 and 6) is the list item → inverse item defined above; `TwistMenu` has no
  such attribute, and the same list is `Mechanics.inverse_word`'s lookup and the checker's `inverse_items`
  (`check_run.py:388-391`). The tests B2, B5, C and D build their own tables from `restore.element` and the
  transposed matrices, on purpose: they check the player's codes and do not reuse them.
- An `ia16` word file (plan §1): gzip with mtime 0 of little-endian uint16 codes, all below 36,000; `word_sha256` over
  the uncompressed bytes; written with `runner_api.Ia16Writer`, and read back with `runner_api.ia16_digest`, as the
  runner does (`runner.py:1337`).

### 4.6 Steps and trees (plan §1 and §3 P3; decided here where marked)

- Steps, in played order:
  - one per cascade orbit with at least one factor: rule `lattice/orbit-<o>`, the factors of `factors_per_orbit` in
    cascade order. An orbit with no factors gets no step and is listed in `report.skipped_orbits` (decided here);
  - one per correction entry k of `run['corrections']`: rule `lattice/correction-<k>-<macro>`, where `<macro>` is the
    library macro index (decided here; families are not unique, for example two `mirror1` entries);
  - retained-first: the orbit steps, then the correction steps; corrections-first: the reverse.
- Fields. No key may be:
  - one of `ROW_KEYS` (`runner.py:66-67`) or `FORBIDDEN_KEYS`; `played_lattice` refuses them (`runner.py:1334`);
  - one of the path keys `file, word, unit, table, library, out` of `check_run.py:50` (`PATH_KEYS`), whose values the
    checker resolves as run paths (`check_run.py:123-132` and :141-163);
  - a closure or certificate key the checker refuses on a lattice row: `parts`, `V_source`, `V_letters`, `V_sha256`
    (`check_run.py:53-54`, :334-338), `construction`, `certificate_sha256` (:423-425).
  Every string anywhere in the record also passes `private_path` (`check_run.py:135-138`): no `\`, no `/` or `~` at
  the start or after a space, `:` or `=`, no drive prefix and no `..` segment.
  - orbit step: `{'orbit', 'factor_first', 'factor_count', 'tree_folded', 'tree_folded_depth'}`;
  - correction step: `{'correction', 'macro', 'family', 'times', 'inverse', 'macro_letters'}`;
  - the last step only: `'labels_identity': true` (plan §1: "`labels_identity` on the last row"; the runner requires
    it, `runner.py:1343-1344`, and the checker allows it only on lattice rows, as a bool, `check_run.py:436-437`).
- Part names: N(j, s) = `<op> <j>` with `op` the node's `op` (`word`, `path`, `conj`, `prod`) and `j` its index in
  `solutions.json`, followed by `⁻¹` when s = −1 (decided here). Names never contain `/`, `\` or `~`; `:` and `->`
  may occur, since library families do (`card5:B4-0`, `diff:W3->I1`). A tree part carries only the keys `name,
  letters, parts, span, inverse_of, same_as` (`check_run.py:78`, :503-505).
- Orbit step tree (plan: "the orbit, then its factors, then the nodes (`conj`, `prod`), then the leaves (`word` and
  `path`) as spans"):
  - root: a group `orbit <o>`; its children: one group `factor <i>` per factor (i within the step), each with exactly
    one child, the node part of its (node, sign);
  - the node part of (j, s) at depth d, written depth-first in played order:
    1. (j, s) already written in this tree: a span named N(j, s) with `same_as` = the index path of its first part;
    2. a `word` or `path` leaf, or a node of zero letters: a span named N(j, s) (`group` rejects empty parts);
    3. d = 64 (`TREE_MAX_DEPTH`): a span, counted in `tree_folded_depth`;
    4. the size reservation fails (below): a span, counted in `tree_folded`;
    5. `conj` {x, u, us}: a group N(j, s) with the children: the node part of (u, −us); the node part of (x, s); and a
       span named N(u, us) with `inverse_of` = the index path of the first child (R3-02: the trailing u^(us) names
       the leading u^(−us); the played order does not change);
    6. `prod`: a group N(j, s) with the node parts of its factors, in order, or reversed with negated signs when s = −1
       (`Program.leaves`, `literal_lattice.py:188-191`).
  - The first part written for each (j, s), whatever its kind, is the one later `same_as` parts name. This includes
    the trailing span of rule 5: when (u, us) has not been written before it, that span named N(u, us) is the first
    part of (u, us), and later occurrences of (u, us) are spans with `same_as` naming it (decided here; `check_tree`
    registers every part, spans with `inverse_of` included, `runner_api.py:197-204`). When (u, us) was written
    before, rule 5 still gives the trailing span `inverse_of`, not `same_as`. A DAG node
    cannot contain itself (`Program.factor`, :162-167), so every `same_as` and `inverse_of` names a part that ends at
    or before the referring part starts. `runner_api.check_tree` (:197-203) and the checker (`check_run.py:537-557`)
    both reject a reference that does not.
  - Size reservation (plan: "a node whose subtree would take the step's tree over 10⁶ parts is written as one span
    named by its node, and the record counts the folded nodes"): keep `committed` = parts written plus parts
    promised (each pending child counts 1). Expanding a node into a group of k children needs
    `committed + k ≤ TREE_PART_LIMIT`; otherwise rule 4 applies. The tree then never exceeds the limit. If the root and
    its factor parts alone exceed it, the whole step is one span `orbit <o>`, counted in `tree_folded`.
- Correction step tree: a group `correction <k>` with `times` spans, each named `macro <m> <family>` (plus `⁻¹` when
  `inverse`) of the macro's length; the second and later carry `same_as: [0]`.
- Every span expands to the twists played; `inverse_of` is the named range inverted letter by letter (through the
  menu's inverse table) and reversed; `same_as` is the named range itself (plan §1).

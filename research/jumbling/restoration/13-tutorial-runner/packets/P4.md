## 4. Necessary source and evidence

### 4.1 The hooks as `97815b1` calls them, and the one entry point decided here

The hooks are the plan's §2 "Hooks (M6)" (README:536-539). At `97815b1`, `check_run.check_run` calls them at
`check_run.py:1197-1231`. The stub documents the same contract (`check_contracts.py:1-16`).

- Which rows: every row of a `runner-run/3` record whose `phase` is `height` or `high`
  (`hooked = v3 and phase in ('height', 'high')`, `check_run.py:1199`). The word may be `json` or `ia16`: both are
  read by `load_word_v3` (:440-462) and replayed the same way. Only lattice rows have no word there (:1080-1083);
  they go to `check_lattice.replay_lattice_step` instead (:1186-1195).
- The replay starts only when no row and no record-level check failed before it (:1101-1112). Otherwise every row is
  reported with its earlier failures, and no hook runs. So in a real check the hooks see rows whose keys, encoding,
  sub-phase, `contract`/`gate` labels and word file are already valid (`check_v3_step`, :399-437). Called directly,
  as the tests do, they may see anything.
- `prepare(row, st) -> ctx` (:1200-1205) runs once per such row, **before** the first letter. `row` is the step dict
  from `run.json`. `st` is the checker's live `sim.State` at the step's start state. The replay changes `st` in place
  (:1207-1216), so `prepare` must copy what it needs. (The checker's own `Snapshot` copies the pose ids and matrices
  when it is made, :191-192, for the same reason, and keeps the live state only until the step ends,
  `self.st = st` :193, `before.st = None` :1232.) `prepare` changes nothing in `st`'s mechanical state (`pose_id`,
  `_poses`, `_lookup`, the digest). `ctx` is any object P4 chooses.
- `on_letter(ctx, k, st)` (:1217-1222) runs after letter `k` (0-based) has been applied and admitted
  (`admitted = outcome.applied and not outcome.uncertain`, :1211), with the same live state. It runs for **high rows
  too**, after every letter. A high row can have thousands of letters (section 6.2, cost).
- `finish(ctx, row, st) -> list[str]` (:1223-1231) runs after the last letter, with `st` at the step's end state. It
  returns the failure names (section 6.2); an empty list means the contract holds. `check_run.py` requires a list of
  non-empty strings and adds each name to the step's failures. `finish` is not called when a letter was not admitted
  (the row then fails `admissible`, :1214-1216).
- An exception from any hook, or a `finish` result that is not a list of non-empty strings, becomes the step failure
  `contract`. After an exception in `prepare` or `on_letter`, no later hook runs for that row (:1203-1205,
  :1220-1222, :1226-1229).
- `unchecked_contract` in a `finish` result marks the row `unchecked` (`step_row`, :1033-1039). It is counted in the
  final row's `unchecked_contracts` and fails the record unless `--allow-unchecked-contracts` is given (`merge`,
  :1041-1046; option :1358-1360). P4 never returns it for a height or high row. The stub's module-level name
  `UNCHECKED = 'unchecked_contract'` (`check_contracts.py:18`) stays. The stub defines no `STUB`, and P4 adds none.
  `check_run.py` reads neither: it has its own `UNCHECKED` (:81).
- **Decided here: `check_high_phase(start, rows) -> list[str]`.** The plan puts the kernel's letter bound,
  6·n6₀ + 964·off₀ counted from the high phase's start state, in P4 (plan §3 P4). No per-row hook sees the phase
  start, and at `97815b1` `check_run.py` has no call for it: it references only `check_contracts.prepare`,
  `on_letter` and `finish` (:1202, :1219, :1225).
  - `start` is a dict with `off` (an int) and `heights` (a histogram `{str(height): count}`). It is either the
    record's `phases.high.start` (`{'digest', 'off', 'heights'}`, set by `Runner.plugin_phase` at `runner.py:606`
    from `Mechanics.snapshot`, `runner.py:251-253`), or the checker's own snapshot at the high phase's start,
    `starts(4)` in `check_v3_phases` (:668-669), as `{'off': snap.count, 'heights': snap.heights()}`
    (`Snapshot.count` :190, `Snapshot.heights` :196-204). The checker already compares the two in
    `check_plugin_phase` (:612-648; the start check is at :633).
  - In an error run, a phase cut off by an exception may keep `result` null with a `start` and steps (I0-V1-01).
    `check_plugin_phase` then checks its start at :624 and its entry test at :625-626. The letter bound applies to
    such a high phase too, so the function does not read `result`.
  - `rows` are the phase's high rows in order. The function returns `['kernel_letter_bound']` when the sum of their
    `letters` exceeds `6 * n6 + 964 * off`, with `n6 = start['heights'].get('6', 0)` and `off = start['off']`. It
    also returns it when `start` or a `letters` value is malformed. Otherwise it returns `[]`.
  - The integrator wires the call into `check_run.py` in I1 (integrator decision 1). P4 does not stop because the
    call is missing. It implements and tests the function and reports the missing call (section 7).
- `check_contracts.py` does not import `check_run.py` (which imports it, `check_run.py:45`), `check_r22d25.py` or
  `check_lattice.py`.

Definitions and decisions. Each one marked "decided here" is not in the plan:
- Max height, n6, n4 and n2 are taken over the off pieces (section 4.7). Max is 0 when no piece is off. "Max ≤ h"
  holds at the step's start and end state, and, for two-letter rules, after letter 1.
- "Falls" and "kept" compare the end state with the start state, using the checker's own counts. "u falls" means own
  u at the end < own u at the start, both at the recorded tau. "Does not rise" means ≤.
- "Every height-H piece kept" (H = 6 for `r22d81/*` and `r22d88/*`, 4 for `h4/*`): every piece at height H in the
  start state is off in the end state with the same exact pose matrix. Together with "nH kept", this makes the
  height-H set unchanged. The r22d81 and pair rules guard this with pose keys (`r22d81_pairs.py:184`;
  `two_letter_u.py:153-155`). The checker compares matrices, because pose ids renumber.
- r22d75 has no u or pose check (plan: "T1 keeps n6, but not the height-6 poses").
- **Decided here, null tau:** at a null tau, u is 0, as the rules count it (`r22d81_rule.py:5-7`, `:234`, `:303`).

### 4.5 The checker's own u (plan §3 P4: "its own per-piece straddle test (`sim` kernel `Evaluator`, `pullback_form`)")

### 6.2 Module interface of `S/check_contracts.py`


Failure names (decided here; the plan names none):
- every row: `contract_phase` (a row whose `phase` is neither `height` nor `high`);
- height rows:
  - `height_rule`: unknown rule, `contract != rule`, or `subphase` not the rule's;
  - `height_fields`: the types of the u fields and `u_mid`, and a tau that is not null on an r22d75 row
    (section 4.3);
  - `height_length`: `letters` is not the rule's 1 or 2;
  - `height_tau`: any invalid tau value: a bool or other non-int, out of 0..599, null where an int is required, or
    `tau_after != tau_before` where the table says "=";
  - `height_u`: `u_before`, `u_after` or `u_mid` differs from the checker's own count at the recorded tau;
  - `height_u_progress`: u does not fall, or rises, against the table;
  - `height_max`; `height_counts` (n6, n4, n2 against the table; for r22d75, the lexicographic fall);
  - `height_tier`: r22d75, the first changed count is not the tier's;
  - `height_poses`: a top-height piece of the start state is not off with the same matrix at the end;
  - `height_guard`: max, a count or a pose fails after letter 1 of a two-letter rule, or the middle state was not
    seen;
- high rows: `kernel_fields`, `kernel_target`, `kernel_collateral`, `kernel_others`, `kernel_high_exact`,
  `kernel_high_exact_pieces`, `kernel_target_height`, `kernel_target_landed`, `kernel_progress`, `kernel_counts`
  (section 4.4); `check_high_phase`: `kernel_letter_bound`.

No other module-level name is required (the plan names none). I1's "count of kernel contract checks" can be read from
`check_run`'s per-step rows (phase `high`, `unchecked` false; `step_row`, `check_run.py:1033-1039`), so P4 exports
no list of contracts.

Cost: `prepare` and `finish` cost one height histogram (per distinct off pose) and at most one u count (one cap)
each. `on_letter` is constant time, except after letter 1 of a two-letter height row. High rows can have thousands of
letters, so `on_letter` must return at once for them.

**`Runner.plugin_phase(phase, sub)`** (`S/runner.py:601-657`) is the only caller of `next_step`.
- It stores the sub-phase's start snapshot first (:606).
- If the entry test fails at the start, the sub-phase is `not_applicable` and the plugin is not called (:608-609).
  The entry tests are in `Runner.entry` (:584-590):
  - `r22d75`: max height ≤ 6 and n4 + n6 > 0;
  - `r22d81`: max ≤ 6 and n6 > 0;
  - `h4`: max ≤ 4 and n4 > 0.
- After each recorded step it re-tests the entry. If the test fails, the sub-phase ends `handoff` without another call
  (:613-615).
- A `Proposal` goes to `record_step` (:620-626). A step that leaves no piece off ends the sub-phase `lattice`
  (:624-625).
- Anything other than a `Proposal` or an `End` raises `ValueError` (:627-628).
- For an `End`:
  - every attempt must carry a bool `timed_out` (:629-630);
  - `handoff` while the entry test holds, or `lattice` while pieces are off, raises `ValueError` (:632-635);
  - `not_applicable` from a non-stub plugin raises `ValueError` (:636-638).
- The `End`'s `reason`, `details` and `attempts` are stored in `phases.height.sub.<sub>` (:644-645).
- `error` sets the height phase's result to `error` (:652-653), saves, and raises `RuntimeError` (:655-656). `run()`
  catches it and records the run as `error` (:1390-1397).
- Any exception out of `plugin_phase` (one of the `ValueError`s above, or one from `record_step`) also ends the run
  `error` through `run()`. But then the sub-phase's `result` and `end` stay null, its `reason`, `details` and
  `attempts` are not stored, and the height phase's result is not set. Its start and earlier steps stand. The checker
  accepts this only in an error run (`check_plugin_phase`, `S/check_run.py:617-629`; `README:942-951`, V1-B2 and
  I0-V1-01).
- `budget` or `timeout` of a sub-phase ends the run `budget` (`phases_between`, `S/runner.py:659-670`, and `run()`,
  :1382-1384; R22D-55).

**How this plugin reports an error (I0 review finding I0-01).**
- In the runner's own rules, a crash, truncated or malformed child output and every digest mismatch raise `RunError`
  (`S/runner.py:317-319`). No rule handler catches it: the run ends `error` at once, no later rule, unit or phase runs,
  and the steps before it stand (`README:101-129`; `README:925-933`).
- `RunError` is defined in `runner.py`. This plugin imports only `runner_api` (6.1), so it cannot raise `RunError`.
  Its equivalent is to **return `api.End('error', reason, details, attempts)`**. `plugin_phase` then stores the reason,
  details and attempts, sets the height result `error` and ends the run `error`, as above.
- Return `End('error', ...)` for: a crash, truncated output, malformed output, a missing STEP, a digest mismatch,
  inconsistent shard output, a cancelled child, a NOT_APPLICABLE line (6.3), and the state-test guards of 6.2.
- Never turn one of these into `stuck`, `budget`, `timeout`, a failed attempt followed by the next script, or a retry.
- Do not raise for them either. A raised exception also ends the run `error`, but the call's attempts and reason are
  lost (above). Raise only for a programming error, such as an unknown `ctx.subphase` (6.1).
- A `stop_when` callback must never raise. `execute` calls it inside its polling loop (:496), and an exception there
  leaves `execute` and the plugin, with the same loss. Guard every parse in the callback.

**`Runner.context(phase, sub)`** (`S/runner.py:592-599`).
- `work_dir` = `<out>/attempts/<steps so far, 5 digits>-<sub>`; the runner creates it (:595-596).
- `budgets` holds the clocks `CLOCKS` (:49-50, among them `height_seconds` and `height_cpu`), plus `pair_shards`,

**`Runner.execute(argv, tag, seconds, *, cwd=None, stop_when=None)`** (`S/runner.py:466-506`).
- Output: stdout and stderr go together to `<out>/logs/<tag>.log`, with `/` in the tag replaced by `-` (:471,
  :488-490).
- If the runner is already cancelling (its `cancel` event is set, or a signal arrived), it returns at once with
  `Child(-1, 0.0, log, cancelled=True)` (:473-474). **The log file does not exist then.** Test `child.cancelled`
  before you open `child.log`.
- `seconds=None` means no clock (:495).
- `stop_when(line)` sees each complete line, decoded as UTF-8 with errors replaced (`watch`, :479-486). When it returns
  true, `execute` kills the process group and returns `stopped` (:496-499).
- The loop polls the process before it reads new lines (:492-496). So a child can print a STEP line and exit on its
  own before `stop_when` sees it. Always parse the log file, never the callback.
- A child killed by the runner (clock, stop or cancel) normally has `rc == -signal.SIGKILL` (`kill_child`,
  :326-349).
- Returns `Child(rc, seconds, log, timeout, cancelled, stopped)` (`Child`, :301-308; returned at :506). `log` is an
  absolute path: never copy it into the record.
- `execute` is safe to call from several threads. `Runner.choose` already does this through a `ThreadPoolExecutor`
  (:1070-1113).

**`Runner.record_step(proposal, phase, sub)`** (`S/runner.py:691-720`).

  (:265-266), after the twists were applied to the runner's state; the run ends `error`.
- It then writes the word file, the tree and `tables/NNNNN.json` (:709-712), and the row (core keys plus `**fields`,
  :713-718), appends it and saves (:719-720).

    - With no target, no L4 letter exists. A cap with an L4 candidate holds own-branch height-4 pieces whole that an
      item lowers, so `target()` lists it with k ≥ 1 (`R/H/h4_unlock.py:147-173`, `:207-223`).
    - U needs tau, so only L2 could fire. After an L2 letter the script would crash at `:314` before printing its
      STEP.
    - L2 keeps every height-4 pose and so keeps the empty target table. Without a target no later step can lower n4,
      and the pair shards need a non-empty table. The sub-phase would end stuck anyway.
    - Record `details.note = 'no target; L2 is not run without a target (h4_unlock.py:314)'`.
  - On STUCK with tau null or an empty `targets` list: `End('stuck', 'no_target')`, with no shards.
  - On STUCK with tau t and a non-empty table: run the `two_letter_u.py` shards (6.5).

### 6.3 Parsing and the error policy

**Order of the checks after a call.**
1. `child.cancelled` → `error`, reason `cancelled`. Do not open `child.log`: it does not exist (4.1, `execute`).
2. Otherwise read `child.log` (UTF-8, errors replaced) and parse it as below.

**Parsing lines.**
- A line counts only when it is complete, that is, terminated by a newline (`stop_when` also sees only complete lines,
  `S/runner.py:485-486`). An unterminated last line is cut: it is ignored, and it never makes the output malformed.
- A line is `TAG <json>`: split at the first space.
- Known tags per dialect are those of section 4.2. Ignore preamble tags (`SNAPSHOT`, `RECORD`, `LOADED`, `U_ITEMS`,
  `SELFCHECK`, `LETTERS`) and lines with other first words (`Terminated`, warnings), except:
  - a line starting with `Traceback` marks a crash;
  - a complete line with a known tag whose payload is not valid JSON makes the output malformed.

**The deciding line.** The first complete STEP line decides; for `h4_unlock.py` only, a START line with tau null
decides in the same way (it comes before any STEP; 6.2). Lines after the deciding line are ignored, whether or not
the child was stopped, and whatever its `rc` (a stopped child has `rc == -SIGKILL`; 4.1, `execute`).

**Ends without a deciding line,** in this order (after the `cancelled` test above):
- `child.timeout` → `timeout`, reason `wall_clock`, `timed_out: true`;
- a known end line (HEIGHT2, HANDOFF, STUCK, UNLOCKED, BUDGET, NOT_APPLICABLE) with `rc == 0` → its mapping, with one
  check. Every one of these end lines except NOT_APPLICABLE carries `steps` (section 4.2). Without a deciding line
  before it, `steps` must be 0. Otherwise the child played a step whose STEP line is missing → `error`, reason
  `missing_step`. Two BUDGET lines are the only exceptions, because these two scripts play and count a letter and
  then check the clock before its STEP line is printed:
  - `r22d81_rule.py`: BUDGET with `steps` 1 and `played_unreported` present with `step` 1 and `family` `H6`. After an
    H6 play the script runs `steps += 1` and then `target()` (`R/r22d81_rule.py:299-301`), which checks the clock
    (`:155`); the BUDGET line then carries the played letter as `played_unreported` (`:309-310`);
  - `h4_unlock.py`: BUDGET with `steps` 1 and `families` equal to `{"L4": 1}`. After an L4 play the script runs
    `steps += 1` and then `target()` (`R/H/h4_unlock.py:310-312`), which checks the clock (`:154`); the BUDGET line
    has no `played_unreported` (`:319-320`).
  - Each maps to `budget`, reason `cpu_budget`, `timed_out: true`, like every BUDGET. The unreported letter is not a
    step and is not recorded. Any other BUDGET with `steps` above 0, and every other mismatch, stays `missing_step`;
- `rc == -signal.SIGXCPU` and `child.seconds` ≥ the `--cpu` value passed → `budget`, reason `cpu_rlimit`,
  `timed_out: true`. **Decision:** the CPU limit is the child's own clock (an attempt that ends on any clock is timed
  out, `README:285-286`). Every soft limit is at least `int(cpu) + 600` CPU seconds and the children are
  single-threaded, so their wall time is then above `cpu` (4.2, "Clocks"; the runner applies the same reading to
  `jordan_target.py`'s cap, `S/runner.py:818-820`). A SIGXCPU before that cannot come from the child's own limit;
- a `Traceback`, or `rc != 0` (an earlier SIGXCPU included) → `error`, reason `crash`;
- anything else, such as `rc == 0` with no end line, or only a cut last line → `error`, reason `truncated`.

**Mapping of the end lines:**

| End line | Result | Reason |
|---|---|---|
| HEIGHT2, HANDOFF | `handoff` | `handoff` |
| r22d75 STUCK | `stuck` | `no_step` |
| r22d81_rule STUCK | as in 6.2 | |
| h4_unlock STUCK | as in 6.2 | |
| r22d81_pairs STUCK | `stuck` | `no_step` |
| UNLOCKED before any STEP | `stuck` | `unlocked_without_step` |
| BUDGET | `budget` | `cpu_budget`, `timed_out: true` |
| NOT_APPLICABLE (from any script that prints it: `r22d81_rule`, `r22d81_pairs`) | `error` | `invariant_height_above_6`, with `details` `{max_height, digest}` from the line |

- The runner judges the claims against the state. It raises `ValueError` on a handoff while the entry test holds, and
  on any non-stub `not_applicable` (4.1). Return the mapped `End` and do not second-guess it.
  - **Integrator decision (20 October 2026), replacing the plan's "NOT_APPLICABLE → `not_applicable`" (4.5):** a
    NOT_APPLICABLE line maps to `End('error', 'invariant_height_above_6', details={'max_height': ..., 'digest':
    ...})`, with both values taken from the line, and carries the call's attempts. This is the reason that the
    pre-call guard (6.2) and the high phase (packet P2) use. The plugin never returns `not_applicable`: from a plugin
    that is not a stub, `plugin_phase` raises `ValueError` on it (`S/runner.py:636-638`), and the call's reason,
    details and attempts would be lost (4.1, V1-B2). For the `End('error', ...)`, `plugin_phase` at `97815b1`:
    - sets the sub-phase's `result` to `error` and its `end` to the current snapshot, and stores the reason, details
      and attempts (:642-645);
    - sets the height phase's result to `error` (:652-653), saves (:654), and raises `RuntimeError('<sub> phase
      error: invariant_height_above_6')` (:655-656);
    - `run()` catches it and records the run as `error`, with that message as its `error` (:1390-1397). The steps
      before it stand, and the later sub-phases keep a null result.
- r22d81's `played_unreported` is ignored apart from the check above: the runner's state did not change.

**Checks on every START and STEP (failure → `error`, reason `digest_mismatch` or `malformed_output`):**
- "The previous line" below means the previous START or STEP line of the same output (other lines, such as
  `U_ITEMS`, are skipped). Each STEP continues from that line: its `input_digest` is that line's `digest`, and
  tau_before, u_before and the r22d75 tier are taken from that line. For the deciding STEP, the only one a call uses,
  it is START. `parse_log` over a committed output with several STEPs (test 1) uses the line before each STEP;
- START's `digest` (CONTEXT's for the shards) equals `snap['digest']`;
- STEP's `input_digest` equals the previous line's `digest` (for the deciding STEP, START's, so `snap['digest']`);
- `digest` is 64 lowercase hex;
- letters are lists of two ints with 0 ≤ grip < 600 and 1 ≤ item ≤ 59. The scripts enumerate `range(1, 60)`;
- the family is one of the script's own;
- `length` agrees with the letters where the dialect prints it: r22d75 and r22d81 1; pairs U 1 and U2 2. h4 has no
  `length`;
- r22d75: STEP's `n6_n4_n2` is lexicographically below the previous line's;
- r22d81 U, H4, H2 and h4 U, L2: STEP tau equals the previous line's tau (only H6 and L4 recompute tau,
  `R/r22d81_rule.py:300-303`, `R/H/h4_unlock.py:311-314`);
- pairs: START tau and STEP tau equal `--target`.
- The claimed end digest is STEP's `digest`. The runner's replay checks it (`record_step`). For the pair step see
  6.5.

**Attempts.**
- Every call made in `next_step` adds one attempt row: `{'script': <name>, 'tag': <tag>, 'shard': <i or null>,
  'outcome': ..., 'reason': ..., 'rc': <int>, 'seconds': <float>, 'stopped': <bool>, 'timed_out': <bool>}`.
  - `outcome` is one of `step, handoff, stuck, unlocked, done, budget, timeout, not_applicable, crash, truncated,
    malformed, mismatch, missing_step, cancelled`.
  - `timed_out` is true exactly for BUDGET, `cpu_rlimit` and the runner's kill.
- A `Proposal` and an `End` both carry all attempts of the call.
- `details` may hold the end line's small fields (`tau`, `u`, `steps`, `n2_n4_n6`, `digest`, `targets`, `best_pair`,
  `limit_cpu`, `max_height`). Never copy log text, tracebacks or paths; no key from 4.1's forbidden and path lists.

### 6.5 The two-letter shards and the pair choice

**Running the shards.**
- n = `ctx.budgets['pair_shards']`. Run shards i = 0 … n−1 concurrently, each `ctx.execute` call in its own thread.
- argv: `--snapshot <pkl> --expect <digest> --shard i --nshards n --cpu <child clock>`;
  `seconds=ctx.wall('height_seconds')`; no `stop_when`. Each shard runs to its own end.
- An early stop once the pair is decided is not required. If you add one, a test must show that it never changes the
  choice.
- Apply the `cancelled` test and the end rules of 6.3 to each shard.

**Checks on the outputs.**
- The checks below apply to the shards that printed a complete CONTEXT line. The script prints CONTEXT only after
  its load and setup (`R/H/two_letter_u.py:46`, `:160-176`), and a cancelled call has no log at all (4.1,
  `execute`). A shard without a CONTEXT line contributes no FIRST line (all its indices are missing) and is judged
  by its end alone, in the order of 6.3:
  - cancelled → `cancelled` (the first row of the mapping below: `error`);
  - killed by the runner (`child.timeout`, or `child.stopped` by an optional early stop) → `timeout` or `stopped`,
    not an error;
  - SIGXCPU that passes the test of 6.3 → `budget`;
  - a `Traceback` or any other `rc != 0` → `crash`;
  - any other end on its own (`rc == 0`, whatever lines it printed) → `truncated`.
- If no shard printed CONTEXT, the outcome is `undecided`.
- Every printed CONTEXT agrees on `digest, tau, u, first_letter_caps, classA, first_letters`.
- Its `shard` and `nshards` match the call.
- `digest` equals the current digest.
- `tau` and `u` equal h4_unlock's STUCK line.
- A DONE line's `first_letters_done` equals that shard's count of complete FIRST lines (`R/H/two_letter_u.py:187`,
  `:217-218` count every FIRST line printed).
- Any disagreement → `error`, reason `inconsistent_output`.

**`choose_pair(outputs)`.**
1. Rebuild the order of 4.2 (e) from the CONTEXT lines (they agree; outputs without one are skipped) and require
   `len(order) == first_letters`.
2. Index the complete FIRST lines (valid JSON, a full line) by `index`. Require `first == order[index]` and the right
   `cls`. Duplicate indices must be identical. Otherwise the output is malformed or inconsistent.
3. Rule 1:
   - Among complete class A lines that are valid, have a non-empty `freed` and a non-empty `successes`, take the
     least first letter in (grip, item) order.
   - It is decided when every class A index whose letter precedes it is complete.
4. Rule 2:
   - It applies only when every class A index is complete and rule 1 has no candidate.
   - Take the least first letter in (grip, item) order over all complete valid lines with a success, in both classes.
   - It is decided when every index whose letter precedes it is complete.
5. The second letter is `successes[0]`. The script appends successes in (h, i) order; check that they are sorted.
6. `exhausted`: every index is complete and no line has a success.
7. Otherwise `undecided`.
- Report each output's end: `done`, `budget`, or `truncated`, the last covering a `Terminated` line, a missing end
  line and a cut last line.

**Mapping for the runner.**

| Outcome | Result |
|---|---|
| Any shard cancelled, crashed (Traceback, or `rc != 0` other than a SIGXCPU that passes the test of 6.3 and other than the runner's own kill: `child.timeout`, or `child.stopped` by an optional early stop), or ended without DONE or BUDGET and was not killed by the runner | `error` (`cancelled`, `crash` or `truncated`), even if the pair is decided |
| `step` | `Proposal('h4/pair')` |
| `exhausted` with every shard DONE, and each DONE's `first_letters_done` equal to that shard's FIRST line count | `stuck`, reason `pair_exhausted` |
| `undecided`, or `exhausted` without every shard ending DONE as in the row above; some shard killed by the runner's clock | `timeout` |
| `undecided`, or `exhausted` without every shard ending DONE as in the row above; otherwise (some shard BUDGET or SIGXCPU as in 6.3) | `budget` |

- A shard that ends BUDGET or is killed after the choice is decided does not prevent the step. Its attempt still
  records `timed_out: true`.

**The pair step's end digest.** The two-letter script prints no digest.
- Compute it with a module-level function `pair_end_digest(ctx, letters)`, which the tests may patch:
  - load a copy with `ctx.mechanics.load(ctx.table)`;
  - apply each letter as `Mechanics.apply_word` does (`S/runner.py:258-267`: a `sim.Twist` from
    `restore.element(menu, c, i)`, admissible and certain);
  - return `copy.digest()`.
- Never apply to `ctx.state`.
- Check that the loaded copy's digest equals `snap['digest']` before applying; otherwise `error`, reason
  `digest_mismatch`.
- The runner replays the step again in `record_step`.

## 1. Goal and acceptance
- Goal: find out whether Godot 4.7 (.NET) can host the S-B drawing method through its own Direct3D 12 RenderingDevice inside the selection gate, and what it constrains (H-09).
- Acceptance, in order; each level starts only when the previous one passed:
  1. **Interop smoke test (no geometry).** A changing, sequence-numbered test texture produced by Direct3D 12 work is displayed through Godot's own D3D12 backend. Device ownership, synchronisation, window resize and teardown all work, and the sequence number shown matches the one produced on every checked frame. Prefer producing the texture on Godot's own device (a RenderingDevice compute or raster pass, or a native resource imported into the RenderingDevice); a shared resource from a second device needs fence synchronisation and is recorded as such.
  2. **Geometry port**, only after an S-B W3 run on the owner's machine has met the gate: W1–W4 inside Godot using the S-B drawing method, with the same geometry check against S-B's `reference_geometry.py` outputs and the same exact label check.
  3. Three cold W3 runs judged by `tools/perf/renderer_gate.py` (candidate name `sa2`).
  4. The first layout specification (H-04, day 6) as the window structure, and the first visual feature list (H-01, day 6) prototyped.
  5. Renderer constraints (H-09) reported by day 8: overlay layers, text in the 3D view, transparency and sorting limits, and how shaders are written (portable HLSL compiled to SPIR-V for Godot's RenderingDevice, or a stated exception with its reason).
- Non-goals: product UI, Look Lab work (the design track owns it), NVIDIA features, DLSS through a GDExtension.

## 2. Actual problem and reproduction
- Godot is the design track's Look Lab framework (protocol section 4). If S-A2 passes, the Look Lab grows into the product shell; if not, the framework-neutral design outputs are rebuilt elsewhere. The open question is whether Godot's renderer path can carry 259,800 slots at full detail inside the gate.

## 6. Constraints and owned files
- Owned files: `work/experiments/renderer-sa2/**` only. Nothing under `native/`, `assets/` or `tools/` changes.
- Synthetic geometry and labels only; never a personal session. Rendering never changes mechanical state or relabels pieces.
- NVIDIA-specific features off and out of the build.
- Time box: window days 3–6 (stage days 5–8), shared with E-2.4-03.
  - Level 1 comes first: the smoke test must show the sequence-numbered texture correctly through Godot's D3D12 backend before any geometry port. The plan sets no earlier cutoff: a smoke test that passes on window day 5 or 6 still allows level 2 within the time box. If it has not passed by the end of window day 6, stop and report the blocking API or behaviour; the day-7 ruling records the candidate as failing.

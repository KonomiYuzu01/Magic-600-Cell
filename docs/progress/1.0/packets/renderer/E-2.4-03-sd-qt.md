## 1. Goal and acceptance
- Goal: find out whether a Qt Quick application can host the S-B drawing method in a `QQuickRhiItem` on the window's QRhi Direct3D 12 backend inside the selection gate, and what it constrains (H-09).
- Acceptance, in order; each level starts only when the previous one passed:
  1. **Interop smoke test (no geometry).** A changing, sequence-numbered test texture produced by Direct3D 12 work is displayed through Qt Quick's own D3D12 backend, on the window's QRhi device (`QQuickRhiItem`), with synchronisation, window resize and teardown working, and the shown sequence number matching the produced one on every checked frame. Native D3D12 work, if any, uses the device and command queue the QRhi exposes; a second device is the fallback and is recorded as such.
  2. **Geometry port**, only after an S-B W3 run on the owner's machine has met the gate: W1–W4 inside the `QQuickRhiItem` using the S-B drawing method, with the same geometry check against S-B's reference outputs and the same exact label check.
  3. Three cold W3 runs judged by `tools/perf/renderer_gate.py` (candidate name `sd`).
  4. The first layout specification (H-04, day 6) as the window structure (Qt Quick items over and around the 3D item), and the first visual feature list (H-01, day 6) prototyped.
  5. Renderer constraints (H-09) reported by day 8: overlay layers, text in the 3D view, transparency and sorting limits, and how shaders are written (portable HLSL through the Qt shader tools, or a stated exception with its reason).
- Non-goals: product UI, Look Lab work, NVIDIA features.

## 2. Actual problem and reproduction
- Qt Quick gives dense, keyboard-first desktop UI and a scene graph that composes UI with a custom 3D item; the open questions are whether its D3D12 path carries the full-detail workload inside the gate and how cleanly the renderer shares the window's device.

## 3. Environment and versions
- Base: `main` with the S-B probe merged (`work/experiments/renderer-sb/`).
- Qt 6 for MSVC x64 at the version pinned in a reviewed lockfile entry (E-2.4-00; `QQuickRhiItem` needs Qt 6.7 or later), installed with `aqtinstall`; CMake 4.4.3 and Ninja 1.13.2 from the `renderer-spike` profile; the MSVC toolset and Windows SDK the owner recorded. The application sets the Qt Quick graphics API to Direct3D 12 (record how, and the backend Qt reports at startup).
- Evidence kind: actual Windows/DirectX and performance, valid only for the built application identity.

## 4. Necessary source and evidence
- S-B outputs: drawing method, `reference_geometry.py` and its reference outputs, the trace-log format, the handoff result.
- Gate and measurement: `docs/wiki/decisions/renderer-candidates.md`; plan section 2; `tools/perf/renderer_gate.py` run format.
- Interop design is checked against requirements R-02, R-04, R-14 and R-17 in [requirements-from-screening](../../requirements-from-screening.md).
- Qt references to verify first (record the version each claim was checked against): `QQuickRhiItem` and `QQuickRhiItemRenderer` (`initialize`, `synchronize`, `render`); `QQuickWindow::setGraphicsApi` with `QSGRendererInterface::Direct3D12`; `QRhi::nativeHandles()` and `QRhiD3D12NativeHandles` (device and command queue); `QRhiTexture::createFrom` for wrapping a native texture; the Qt shader tools (`qsb`) for HLSL input.

## 6. Constraints and owned files
- Owned files: `work/experiments/renderer-sd/**` only. Nothing under `native/`, `assets/` or `tools/` changes. Qt binaries are never committed.
- Synthetic geometry and labels only; never a personal session. Rendering never changes mechanical state or relabels pieces.

- Licence: Qt is used under the LGPL with dynamic linking for this spike; any other licence choice is an owner decision.
- Time box: window days 3–6 (stage days 5–8), shared with E-2.4-02.
  - Level 1 comes first: the smoke test must show the sequence-numbered texture correctly through Qt Quick's D3D12 backend before any geometry port. The plan sets no earlier cutoff: a smoke test that passes on window day 5 or 6 still allows level 2 within the time box.

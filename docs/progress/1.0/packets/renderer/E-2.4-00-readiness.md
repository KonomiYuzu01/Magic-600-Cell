# Packet E-2.4-00: renderer window readiness (by stage day 3)

Run in the local Windows session. This packet is a checklist for the owner and the local Claude session; it has no Codex implementation step.

## 1. Goal and acceptance
- Goal: before stage day 3, every tool the renderer window needs is installed at an approved exact version, a minimal Direct3D 12 program builds and presents on the discrete GPU, and the gate judge parses a real short capture. Setup failures are recorded as setup failures, never as renderer results (plan section 3).
- Acceptance:
  1. `python tools/toolchain/bootstrap.py check` reports every tool in the table of section 4 as installed at its pinned version, or the table records why one is not needed yet.
  2. A minimal D3D12 program (clear and present, about 50 lines; the S-B packet may reuse it) builds with CMake and Ninja and presents on the RTX 4070 Laptop GPU, confirmed in the NVIDIA Control Panel.
  3. A 20-second PresentMon 2.6.0.0 capture of that program, taken from an administrator terminal with `--v1_metrics --qpc_time --process_id <pid> --output_file <run>/presentmon.csv`, with a hand-written `run.json` (scene `w1`, format `magic600-renderer-run-v1`), is read by `python tools/perf/renderer_gate.py <run> --out <summary.json>` and listed as invalid with reason `capture-short` (or `capture-not-covered`), not as unreadable.
  4. `python tools/perf/check_renderer_assets.py` passes on the owner's checkout.
- Non-goals: any renderer result, timing claim or tool not in the table.

## 2. Actual problem and reproduction
- The renderer profiles were assembled on 29 September to 1 October 2026. Some entries are verified and installed, some are unverified winget entries that need a pin on the owner's machine, and some tools have no lockfile entry yet (section 4).

- Evidence kind: setup only. Item 3 is a parser check, not performance evidence.
